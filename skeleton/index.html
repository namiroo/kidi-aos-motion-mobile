원칙

짧은 대기(1초 안팎)는 Spinner, 목록·카드·상세처럼 형태를 미리 알 수 있는 화면은 Skeleton을 씁니다. 한 화면에 둘을 섞지 않습니다.

무엇을 바꾸나

서버 값만 Skeleton — 업체명·보험사명·번호·날짜·금액·심볼·상태 뱃지·목록 행. 앱바·탭·검색 영역·섹션 제목·필드 라벨·하단 버튼은 실제 마크업 그대로.

감싸는 요소는 남긴다

.card-value 같은 원래 요소 안의 텍스트만 .sk로 바꿉니다. 글자 크기·행간이 유지돼 로딩이 끝나도 화면이 흔들리지 않습니다.

개수

개수를 모르는 목록은 첫 화면분만 — 홈 최근 내역 5행, 카드 목록 4장. 상세는 실제 행 수 그대로.

폭

실제 텍스트의 평균 폭으로. 같은 열은 같은 폭, 여러 줄이면 마지막 줄을 60~70%로.

상호작용

Skeleton 영역은 누를 수 없음(aria-busy="true" 영역의 링크·버튼 비활성). 데이터가 필요한 하단 버튼은 disabled.

전환 타이밍

300ms 안에 응답이 오면 Skeleton을 띄우지 않음. 띄웠으면 최소 300ms 유지 후 200ms 페이드로 교체.

오류·빈 결과

실패하면 Error/Empty State로 바꾸고, 무한 Skeleton으로 두지 않음.

접근성

데이터 영역에 aria-busy="true", Skeleton 요소는 aria-hidden="true". 스크린리더에는 “불러오는 중”을 한 번만 안내. 동작 줄이기 설정 시 Shimmer 정지(CSS에 포함).

토큰

Figma 변수 AOS Color/07_skeleton/*와 같은 값입니다. 바탕이 회색이면 bone이 묻히므로 한 단계 진한 값을 쓰는 클래스를 감싼 요소에 붙입니다.

Primitive 모든 Skeleton은 이 네 가지로 조립합니다

.sk-line — 인라인 줄 (가장 많이 씀)

값을 감싸던 요소 안에 넣습니다. 부모의 font-size·line-height를 따라가 행 높이가 실제와 같습니다. 폭은 --w.

차량정보
접수번호 
<!-- 실제 -->
<span class="card-value">11가4564, 싼타페(SANT)</span>
<!-- 로딩 중 -->
<span class="card-value"><span class="sk sk-line" style="--w:150px" aria-hidden="true"></span></span>

.sk-text — 블록 텍스트

감쌀 요소가 없을 때. 높이=행간, 막대=글자보다 조금 작게. Figma skeleton/text와 1:1.

<div class="sk-text sk-text--title" style="--w:170px" aria-hidden="true"></div>
<!-- heading 28/18 · title 26/16 · body 22/14 · label 20/12 · caption 18/10 (행간/막대 px) -->

.sk-circle — 원

보험사 심볼·아이콘. --s 또는 .sk-circle--20/24/32/40/48.

<span class="sk sk-circle sk-circle--24" aria-hidden="true"></span>

.sk-box — 박스

뱃지(4)·입력창/버튼(8)·카드/타일(12). --w --h로 크기.

<span class="sk sk-box sk-box--badge"></span>            <!-- 상태 뱃지 48×22 -->
<span class="sk sk-box sk-box--field"></span>            <!-- 입력창 높이 48 -->
<span class="sk sk-box sk-box--r12" style="--w:120px;--h:80px"></span>

상태 전환 300ms 지연 표시 · 최소 300ms 유지 · 200ms 페이드

데모 — 응답 시간을 골라 보세요

    구현 예시 (Vanilla JS)

    /**
 * 데이터 영역에 Skeleton 을 띄우고 응답이 오면 교체합니다.
 * - 300ms 안에 끝나면 Skeleton 을 아예 띄우지 않음 (깜빡임 방지)
 * - 한 번 띄웠으면 최소 300ms 유지
 */
async function loadWithSkeleton(region, request, render, skeletonHTML) {
  const DELAY = 300, MIN = 300;
  let shownAt = 0;
  const timer = setTimeout(() => {
    region.setAttribute('aria-busy', 'true');
    region.innerHTML = skeletonHTML;          // 예: .sk-card × 4
    shownAt = performance.now();
  }, DELAY);
  try {
    const data = await request();
    clearTimeout(timer);
    if (shownAt) {
      const left = MIN - (performance.now() - shownAt);
      if (left > 0) await new Promise(r => setTimeout(r, left));
    }
    region.innerHTML = render(data);
    region.classList.add('sk-fade-in');
  } catch (e) {
    clearTimeout(timer);
    region.innerHTML = renderError(e);        // Error / Empty State 로 교체
  } finally {
    region.setAttribute('aria-busy', 'false');
  }
}

    개발 체크리스트

    • skeleton.css를 페이지 CSS 뒤에 불러온다 (page.css 다음).
    • aria-busy="true"는 데이터 영역(main·목록·시트)에만 — 앱바·하단 버튼에는 붙이지 않는다.
    • 값을 감싸는 원래 요소는 남기고 안쪽만 .sk로 — 로딩 전후 높이가 같아야 한다.
    • 목록은 첫 화면분(홈 5행·카드 4장)만 그린다.
    • 회색 바탕 위에는 .sk-on-sunken(gray/100) · .sk-on-muted(gray/200)를 감싼 요소에.
    • 300ms 지연 · 최소 300ms 유지 · 200ms 페이드 (위 예시 함수).
    • 오류·빈 결과는 Skeleton을 남기지 말고 Error/Empty State로 교체.
    • Spinner와 같은 화면에서 동시에 쓰지 않는다.
